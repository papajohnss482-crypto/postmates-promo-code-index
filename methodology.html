Methodology

Two kinds of records, two kinds of evidence

Verified in-app. Programs with this label were seen on screens inside the official Postmates app, on the dates printed with them. In October 2026 that covers the Uber One trial and price, the $12 Meal Deals structure, and the referral amounts. In-app evidence is the strongest available, because it is what a user's own account will honor.

Community-reported. Codes with this label were shared by users who reported them working, and collected from public deal communities by the source publication. They carry the date they were checked against those reports. They are never described as tested, because nobody outside Postmates can truly test whether a targeted code will accept a different account.

The source record

This dataset is a versioned snapshot of the live list maintained at postmatescoupons.us, the source publication for this index. The snapshot on this site reflects the source as published on October 17, 2026. Between snapshots, the live list is the newer record. When the two differ, believe the live list and treat this dataset as the dated snapshot it declares itself to be.

Rules on dates

  • Last checked is the genuine date of the check. It is never edited forward.
  • Expiry printed by listing sources is recorded as per community reports (unverified), because tracking shows listing countdowns being extended while the offer itself does not change.
  • Where the source record prints a specific expiry date, the dataset reproduces it and says so, for example the October 25, 2026 date on eats-q1zgtnn8i6.
  • Snapshot dates and publication dates are always shown separately, so a reader can see both when the data was checked and when this file was made.

Rules on delisting

When a code is delisted at its source, the next dataset version removes it and the removal is written into the changelog with a date. Delisted codes are dropped, never held with a new expiry, and never left in the table marked as current. The changelog is the dataset's memory: additions, removals, and corrections all stay visible there.

Known limits of version 1.0

  • The community code records were checked on October 2, 2026. They are the honest state of the record, and they are aging. The next snapshot follows the source publication's next check cycle.
  • Targeting is invisible from outside. The dataset records scope exactly as reported, for example the Las Vegas restriction on FINALKICK, but only the app can confirm assignment to a specific account.
  • Grocery and restaurant offer tags are location specific and are not code records, so they are described in research publications rather than listed here as data.

Postmates Promo Code Index is an independent open dataset, not affiliated with Postmates or Uber.
